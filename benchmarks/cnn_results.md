# CNN / Transformer Benchmark Results

Unlike `RESULTS.md` (which is auto-regenerated by `make bench` and covers only the
classical/shallow-ML baselines from Phase 2), this file is a hand-assembled record of
real training-cluster results for the neural architectures from Phase 3/4. It is not
regenerated by a script -- every number here was pulled directly from a completed SLURM
job's evaluation output against the official Sen1Floods11 test split (90 chips), and the
source checkpoint's job ID is cited so any number can be traced back to the job that
produced it. Compare against the classical baselines in `RESULTS.md`: Otsu 0.304, Otsu +
HAND 0.281, Random Forest 0.233 (mean IoU, same test split).

## Interpretation

**None of the three single-feature removals produce a clear drop.** Run-to-run seed
variance alone is already ~0.009-0.010 mean IoU on this dataset (see the 3-seed std
columns above), and every leave-one-out delta (-0.011 to -0.001) falls inside that band.
"No ratio" shows the largest drop and is the best candidate for a real (if small) effect,
but it needs a 3-seed run before treating it as more than noise -- flagged here as a
concrete follow-up, not run tonight to keep the ablation sweep inside one GPU-budget
session.

**The bigger, more surprising result is the VV+VH-only row**: dropping all three derived
channels (ratio, slope, HAND) *simultaneously* only costs 0.006 mean IoU -- smaller than
one seed's worth of ordinary variance. On this dataset, at this chip size, with a
ResNet-34 encoder, the derived/terrain channels are not earning a measurable accuracy
improvement as raw CNN input, even though HAND in particular is the single most
recommended auxiliary feature for SAR flood mapping in the literature (spec section 3.2).
That doesn't mean HAND is worthless for this project overall -- its physical role in
permanent-water differencing (Track B, scene-scale inference) is a different use than
"one more channel a ResNet encoder has to learn to read," and the classical Otsu+HAND
baseline is a separate, already-measured comparison. But as a literal input channel to
this specific architecture, it is not paying for its complexity on this benchmark.

**Architecture comparison**: SegFormer-B2 (no-TTA, 0.4344) and U-Net++ with TTA (0.4335)
are effectively tied for the best accuracy on this benchmark, both modestly ahead of the
primary U-Net baseline (0.415). That's a genuine data point against the spec's own prior
expectation that "the CNN inductive bias likely wins" on a dataset this small (section
4.1) -- the transformer is not losing here. DeepLabV3+ clearly underperforms (0.3783),
and TTA is not a universal win: it helped U-Net++ (+0.007) but slightly hurt SegFormer-B2
(-0.0055), so it isn't safe to assume test-time augmentation always helps without
checking per architecture.

**ChangeAwareUNet underperforms the plain U-Net baseline** (0.398 ± 0.010 vs 0.415 ±
0.009), despite the added two-stream JRC-baseline fusion and extra model complexity. This
is consistent with a caveat already recorded in the model's own docstring
(`models/change_aware_unet.py`): Sen1Floods11 ships single-timestamp chips, not true
(pre-flood, during-flood) pairs, so the permanent-water mask is only a proxy for "what
this pixel looked like before," and that proxy may not carry enough signal for the
two-stream design to earn back its added complexity on this specific dataset.
